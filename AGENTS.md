# РСО Портал: правила работы агентов

Эти инструкции действуют для всего репозитория.

## Общий процесс

Для каждой нетривиальной задачи координатор должен провести работу через четыре
этапа:

1. Сформулировать критерии приёмки и определить затрагиваемые компоненты.
2. Передать реализацию агенту-разработчику.
3. После реализации передать итоговый diff независимому агенту-ревьюеру и
   агенту-тестировщику.
4. Вернуть замечания разработчику, повторить проверки и только затем сообщить о
   завершении задачи.

Ревью и тестирование разрешено выполнять параллельно, когда они проверяют уже
сформированный и стабильный diff. Разработчик не должен менять проверяемые файлы,
пока ревьюер и тестировщик не завершили текущий проход.

## Координатор

- Перед началом работы проверяет состояние Git и сохраняет пользовательские
  изменения.
- Формулирует конкретные критерии приёмки.
- Разделяет работу только на независимые задачи с понятными границами.
- Следит, чтобы разные агенты одновременно не редактировали одни и те же файлы.
- Не объявляет задачу завершённой, пока остаются замечания P0/P1, падают
  обязательные проверки или не выполнены критерии приёмки.
- В итоговом отчёте перечисляет изменения, выполненные проверки, результаты
  ревью и оставшиеся риски.

## Агент-разработчик

- Имеет право изменять код и тесты только в пределах поставленной задачи.
- Перед изменениями изучает существующую архитектуру и соглашения проекта.
- Не исправляет посторонние проблемы без согласования с координатором.
- Добавляет содержательные тесты для нового поведения и исправленных ошибок.
- Не подменяет реальные проверки тестами, повторяющими реализацию.
- Перед передачей работы запускает относящиеся к изменению тесты и статические
  проверки и сообщает точные команды и результаты.

## Агент-ревьюер

- Работает в режиме только чтения и не изменяет файлы.
- Проверяет итоговый diff, а при необходимости читает связанный код.
- Ищет ошибки логики, регрессии, проблемы безопасности, потерю данных,
  несовместимость API и схемы БД, некорректную обработку ошибок, состояния гонки
  и недостаточные тесты.
- Не требует косметических изменений, не влияющих на поддержку или корректность.
- Каждое замечание содержит приоритет, файл и строку, сценарий проявления и
  предлагаемое направление исправления.

Приоритеты замечаний:

- P0 — немедленная критическая проблема; выпуск невозможен.
- P1 — серьёзная ошибка или уязвимость; исправление обязательно.
- P2 — реальный дефект или существенный риск; обычно исправляется до слияния.
- P3 — необязательное улучшение.

Если существенных замечаний нет, ревьюер явно сообщает об этом и указывает, что
осталось непроверенным.

## Агент-тестировщик

- Не изменяет production-код.
- Проверяет критерии приёмки независимо от реализации разработчика.
- Запускает доступные автоматические тесты, линтер, проверку форматирования,
  типизацию, анализ безопасности и аудит зависимостей.
- Для исправлений ошибок по возможности воспроизводит исходную ошибку и
  подтверждает, что исправление устраняет её.
- Добавлять или менять тесты может только по отдельному поручению координатора.
- Сообщает точные команды, результаты, обнаруженные сбои и непроверенные области.

## Правила качества и безопасности

- Секреты, токены, персональные данные, базы SQLite и пользовательские документы
  нельзя добавлять в Git.
- Изменения схемы БД должны сохранять существующие данные или включать явный и
  проверенный путь миграции.
- Внешние вызовы должны иметь таймауты и контролируемую обработку ошибок.
- Публичные API, статусы обращений и пользовательские сценарии нельзя менять без
  обновления тестов и описания совместимости.
- Новые зависимости требуют объяснения необходимости и проверки известных
  уязвимостей.

## Условия завершения задачи

Задача готова только когда:

- выполнены критерии приёмки;
- пройдены относящиеся к изменению тесты и обязательные статические проверки;
- независимое ревью завершено;
- замечания P0 и P1 устранены;
- замечания P2 устранены либо явно приняты владельцем проекта;
- итоговый отчёт содержит известные ограничения и оставшиеся риски.
