Канал доставки кода — **только e-mail**. SMS не используется в этой версии.

Авторизация **одноразовая**: после успешной проверки кода связка
`chat_id ↔ ЛС` сохраняется бессрочно, повторно код не запрашивается.

## 1. Нештатные ситуации — как их обрабатывать

| Ситуация | Кто определяет | Ответ бота пользователю |
|---|---|---|
| Лицевой счёт не найден в 1С | 1С | «Лицевой счёт не найден. Проверьте номер и попробуйте снова.» |
| ЛС найден, но в карточке нет e-mail | 1С | «Авторизация невозможна: не заполнен контактный e-mail. Обратитесь в контактный центр.» |
| Код введён неверно | 1С | «Код неверный, попробуйте ввести ещё раз.» (возврат к вводу кода, тот же ЛС) |
| Код истёк | 1С (срок действия — 10 минут; Python правило не дублирует) | Статус `expired_code`, сообщение об истечении, возврат в главное меню |
| Попытки исчерпаны | 1С (максимум 5 неверных попыток; Python их не считает) | Статус `attempts_exceeded`, сообщение об исчерпании попыток, возврат в главное меню |
| 1С не отвечает дольше 5 секунд | FastAPI (таймаут) | «Сервис авторизации временно недоступен. Попробуйте позже.» |
| Флаг интеграции выключен на этом сервере | FastAPI/бот не вызывают 1С вообще | Пункт меню «Авторизоваться» не показывается — см. раздел 5 |

## 2. Раздел для Python-разработчика (наша сторона)

### 2.1 Новый флаг конфигурации

`config.py`:
```python
ENABLE_1C_INTEGRATION: bool = os.getenv("ENABLE_1C_INTEGRATION", "false").lower() == "true"
INTEGRATION_1C_BASE_URL: str = os.getenv("INTEGRATION_1C_BASE_URL", "")
INTEGRATION_1C_AUTH_TOKEN: str = os.getenv("INTEGRATION_1C_AUTH_TOKEN", "")
INTEGRATION_1C_TIMEOUT_SECONDS: int = int(os.getenv("INTEGRATION_1C_TIMEOUT_SECONDS", "5"))
```
Флаг — на уровне `.env` конкретного VPS. Клиент либо целиком на 1С, либо
целиком на текущей схеме (ЛС проверяется по локальной `licschet` из Excel).
Смешанного режима нет.

### 2.2 Новый модуль `client_1c.py`

По аналогии с `client_api.py` — синхронный httpx-клиент, вызывается **только**
из FastAPI-процесса (`api/`), никогда напрямую из `bot.py`.

```python
def request_auth_code(ls: str) -> tuple[dict | None, str | None]:
    """POST {INTEGRATION_1C_BASE_URL}/auth/request-code"""

def verify_auth_code(ls: str, code: str) -> tuple[dict | None, str | None]:
    """POST {INTEGRATION_1C_BASE_URL}/auth/verify-code"""
```
Таймаут запроса — `INTEGRATION_1C_TIMEOUT_SECONDS` (5 сек по умолчанию).
Механизм авторизации наших запросов к 1С — **открытый вопрос**, см. раздел 4.

### 2.3 Новые эндпоинты FastAPI

Защищены как обычно — `Bearer INTERNAL_API_TOKEN` (это НЕ то же самое, что
`INTEGRATION_1C_AUTH_TOKEN`, который используется в обратную сторону, для
запросов FastAPI → 1С).

**`POST /api/v1/integrations/1c/auth/request-code`**
```json
// Запрос
{ "ls": "100001" }

// Ответ 200
{ "status": "sent" }
{ "status": "ls_not_found" }
{ "status": "no_contact" }

// Ответ 504 (таймаут 1С) — бот показывает "сервис временно недоступен"
```

**`POST /api/v1/integrations/1c/auth/verify-code`**
```json
// Запрос
{ "ls": "100001", "chat_id": 123456789, "code": "482910" }

// Ответ 200 — код верный
{
  "status": "ok",
  "meters": [
    { "meter_number": "СЭ-001", "resource_type": "Электроэнергия", "meter_type": "Однотарифный" },
    { "meter_number": "СЭ-002", "resource_type": "Электроэнергия", "meter_type": "Двухтарифный" }
  ]
}

// Ответ 200 — код неверный
{ "status": "wrong_code" }
```
При `status: "ok"`:
1. `chat_id ↔ ls` сохраняется в `bot_users` (как и сейчас для обычного флоу)
2. Полученные `meters` записываются в `schetchiki` (upsert по паре `ls` + `meter_number`)
3. Для новых записей `initial1`/`initial2` проставляются в `"0"` — 1С не
   передаёт начальные показания в этой части интеграции (см. п. 2.5)

### 2.4 Изменения в `bot.py`

Текущий универсальный флоу «введите ЛС» (`_request_ls()` / состояние
`AWAIT_LS` / таблица `_AFTER_LS_ACTIONS`) используется **во всех** сценариях:
обращения, показания, запись на приём, квитанция. При включённом
`ENABLE_1C_INTEGRATION` этот флоу **полностью заменяется** на новый
двухшаговый (запрос кода → ввод кода), а не дополняется — то есть если
1С-интеграция включена, обратной совместимости со старым «просто введите
ЛС» для этого VPS нет.

Новые состояния сессии:
```python
S.AWAIT_LS_1C     = "await_ls_1c"      # ввод ЛС перед запросом кода
S.AWAIT_CODE_1C   = "await_code_1c"    # ввод кода из письма
```
Пункт главного меню «Авторизоваться» — показывается **только** если
`ENABLE_1C_INTEGRATION=True` (иначе флоу вообще не нужен, ЛС проверяется
неявно как сейчас).

### 2.5 Важное техническое допущение — зафиксировано и уточнено в Части 2

`schetchiki`, полученные из 1С при авторизации, **не содержат исходных
показаний** (в отличие от Excel-загрузки, где `initial1`/`initial2` брались
из файла). Для таких счётчиков `initial1`/`initial2` проставляются в
`"0"` — исключительно для целостности схемы таблицы (поля со значением по
умолчанию), не для бизнес-логики.

**Уточнение из Части 2:** при включённой 1С-интеграции локальная проверка
«новое показание ≥ предыдущего» **не выполняется вообще**, ни для новых,
ни для старых счётчиков — решение шире, чем просто это конкретное поле.
Полное обоснование и связанные следствия (что происходит с историей
показаний в портале) — раздел 1.1 документа Части 2, читать оттуда как
источник истины по этому вопросу.

### 2.6 Логирование — обязательное требование

Код авторизации и e-mail клиента — персональные данные и одноразовый
секрет. **Никогда не писать в лог-файл**: ни сам код, ни адрес e-mail, ни
тело запроса/ответа целиком. Логировать только факт события без
содержимого:
```python
log.info("Запрошен код авторизации: ls=%s", ls)               # можно
log.info("Код авторизации введён: ls=%s  chat_id=%s", ls, chat_id)  # можно
log.info("Код авторизации: %s", code)                          # НЕЛЬЗЯ
```

## 3. Раздел для 1С-разработчика (внешняя сторона)

Наша сторона (FastAPI) будет обращаться к HTTP-сервису 1С по двум
эндпоинтам. Ниже — ожидаемый контракт со стороны 1С.

### 3.1 Требование по времени ответа

**Оба эндпоинта должны отвечать не дольше 5 секунд.** Наша сторона
работает с ботом в режиме реального диалога с пользователем — при более
долгом ответе мы считаем 1С недоступной и показываем пользователю
ошибку. Если 5 секунд недостаточно для генерации кода и отправки письма —
сообщите нам, обсудим увеличение таймаута с нашей стороны отдельно.

### 3.2 `POST /auth/request-code`

Принимает номер лицевого счёта и `chat_id` (MaxUserID), должен:
1. Проверить существование ЛС
2. Если ЛС найден и в карточке есть e-mail — сгенерировать код, отправить письмом, вернуть `"status": "sent"`
3. Если ЛС не найден — вернуть `"status": "ls_not_found"`
4. Если ЛС найден, но e-mail не заполнен — вернуть `"status": "no_contact"`, **не** пытаясь отправить письмо

```json
// Запрос от нас к вам
{ "ls": "100001", "chat_id": 123456789 }

// Ваш ответ
{ "status": "sent", "message": "Код отправлен на электронную почту" }
{ "status": "ls_not_found", "message": "Лицевой счёт не найден" }
{ "status": "no_contact", "message": "Для лицевого счёта не указан e-mail" }
```

**Важно:** в ответе не нужно возвращать сам e-mail или его часть — нам
это не требуется, а хранить у себя чужой e-mail без необходимости мы не
хотим.

### 3.3 `POST /auth/verify-code`

Принимает ЛС, `chat_id` и введённый пользователем код, должен:
1. Проверить код на стороне 1С: срок действия 10 минут, максимум 5 неверных попыток
2. Если код верный — сохранить связку `chat_id ↔ ЛС`, вернуть `"status": "ok"` и список счётчиков
3. Различать неверный код (`wrong_code`), истёкший (`expired_code`) и исчерпанные попытки (`attempts_exceeded`)

```json
// Запрос от нас к вам
{ "ls": "100001", "chat_id": 123456789, "code": "482910" }

// Ваш ответ — код верный
{
  "status": "ok",
  "message": "Авторизация выполнена",
  "meters": [
    { "meter_number": "СЭ-001", "resource_type": "Электроэнергия", "meter_type": "Однотарифный" },
    { "meter_number": "СЭ-002", "resource_type": "Электроэнергия", "meter_type": "Двухтарифный" }
  ]
}

// Ваши ответы при ошибках
{ "status": "wrong_code", "message": "Код неверный" }
{ "status": "expired_code", "message": "Срок действия кода истёк" }
{ "status": "attempts_exceeded", "message": "Число попыток исчерпано" }
```

**Поле `meter_type`** — строго одно из двух значений: `"Однотарифный"` или
`"Двухтарифный"`. Если у вас есть другие типы счётчиков (многотарифные,
двунаправленные и т.п.) — сообщите нам до начала разработки, текущая схема
их не поддерживает.

### 3.4 Открытый вопрос — авторизация наших запросов к вам

Нужен согласованный способ, которым мы подтверждаем свою легитимность при
обращении к вашему HTTP-сервису — например, статический токен в заголовке
запроса, Basic Auth, или IP-whitelist по адресу нашего сервера. Выбор
зависит от того, что уже поддерживает ваш HTTP-сервис — сообщите
предпочтительный вариант, мы адаптируемся.
